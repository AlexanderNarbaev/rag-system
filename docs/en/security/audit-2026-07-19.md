# Security Audit & Penetration Test Report — 2026-07-19

> **Scope.** First-line audit of the RAG proxy: authentication, rate limiting,
> access control, input validation, security headers, and dependency
> configuration. Tests live in `tests/security/` and the dependency scan
> driver in `scripts/security_audit.sh`.

| Area | Status | Notes |

## 2. Critical issues

No new CVSS ≥ 7 issues were introduced by the audit suite itself. Two
**existing** weaknesses were observed and codified as `xfail` cases so the
gap remains visible until a fix lands.

1. **Message history is unbounded** — `proxy/app/api/chat.py`
   `ChatCompletionRequest.messages` has no `max_length` constraint. A
   malicious client can send thousands of past messages, blowing the LLM
   context window. Tracked by `test_very_deep_message_history_is_truncated`
   (`xfail`). Mitigation: add `Field(..., max_length=100)` on `ChatMessage`
   or a model validator.
2. **LDAP DN injection** — `proxy/app/auth/ldap.py` `_build_user_dn`
   performs raw `str.replace` of `{username}`. A username containing
   `,`, `=`, `\` or NUL allows DN manipulation. Tracked by
   `test_ldap_injection_in_user_search_is_escaped` (`xfail`). Mitigation:
   escape the `username` per RFC 4514 (e.g. `ldap3.utils.conv.escape_rdn`).

## 3. Recommendations

1. **Wire the new tests into CI.** Add `tests/security/` to the `pytest`
   collection root and run `make test-security` (or equivalent) as a
   required gate alongside `make lint` / `make typecheck`.
2. **Run the dependency scanner nightly.** Schedule
   `scripts/security_audit.sh` in CI; ensure `pip-audit` is installed in
   the runner. Fail the build on `pip-audit --strict` regressions.
3. **Track the two `xfail` findings to closure.** Open issues for the
   message-history cap and the LDAP DN escape; remove the `xfail` markers
   once the production code is fixed.
4. **Rotate the JWT secret on schedule.** `proxy/app/shared/config.py`
   auto-generates an ephemeral secret when none is provided — that
   invalidates all tokens on restart. Production deployments must set
   `JWT_SECRET` via a secret manager and rotate quarterly.
5. **Tighten the rate-limit budget for `/v1/auth/login`.** A flood of
   failed logins is still a brute-force surface; the existing
   `RateLimitMiddleware` helps but a dedicated stricter budget on
   `/v1/auth/login` is recommended.
