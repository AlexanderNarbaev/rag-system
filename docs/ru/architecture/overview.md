# Архитектура RAG-системы

## Верхнеуровневая схема

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   ETL Pipeline  │ ──> │  Vector Store   │ <── │  RAG Proxy      │
│  (etl/)         │     │  (Qdrant)       │     │  (proxy/)       │
│                 │     │                 │     │                 │
│ • 6 extractors  │     │ • Dense + Sparse│     │ • FastAPI       │
│ • Semantic chunk│     │ • RRF Fusion    │     │ • Granian ASGI  │
│ • Embedding     │     │ • ACL filters   │     │ • Multi-provider│
│ • Graph (Neo4j) │     │                 │     │ • LangGraph     │
└─────────────────┘     └─────────────────┘     └─────────────────┘
         │                                               │
         │              ┌─────────────────┐              │
         └────────────> │  Model Evolution│ <────────────┘
                        │  Service        │
                        │  (port 8090)    │
                        └─────────────────┘
```

## Поток данных

### Индексация

1. Извлечение (Confluence/Jira/GitLab/документы/книги/чаты)
2. Семантический чанкинг
3. Генерация SHA-256 хэша
4. Создание эмбеддингов с помощью BGE-M3
5. Индексация в Qdrant

### Запрос

1. Пользователь отправляет чат-запрос с model+RAG
2. Переписывание запроса (SLM)
3. Гибридный поиск (dense + sparse, RRF)
4. Реранкинг (BGE-Reranker-v2-m3)
5. Сборка контекста (дедупликация, бюджет токенов)
6. Генерация (LLM)
7. Проверка уверенности и обоснованности ответа
8. Возврат ответа

### HITL-обратная связь

1. Эксперт отправляет обратную связь через /v1/feedback
2. Сохранение в SQLite
3. Экспорт в JSONL
4. Model Evolution обучает адаптер
5. AdapterManager выполняет горячую перезагрузку

## Ключевые архитектурные решения

- **OpenAI-совместимость**: drop-in замена для любого клиента
- **Маршрутизация +RAG**: прозрачна для OpenWebUI
- **Мультипровайдерный LLM**: vLLM, llama.cpp или OpenAI-совместимый
- **Автономность (air-gapped)**: все модели предзагружены
- **Грациозная деградация**: каждый компонент отказывает независимо
- **DDD-архитектура**: доменные модели с сущностями, объектами-значениями и событиями
