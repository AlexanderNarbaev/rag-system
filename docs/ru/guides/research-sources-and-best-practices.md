# Исследовательские источники и интеграция лучших практик

> **Статус:** живой документ. Полная ревизия: 24.08.2026.
> Каталог внешних источников, изученных в ходе аудита проекта, и сопоставление каждой distilled-практики
> со статусом реализации в репозитории. Документ — мост прослеживаемости между отраслевыми знаниями и нашим кодом.

## 1. Цель и методика

В ходе аудитовой волны 24.08.2026 проанализировано 36 внешних источников (инженерные статьи Habr, статья
arXiv, блоги практиков, методические ресурсы). Из каждого источника извлечены конкретные практики, каждая
практика классифицирована по фактическому состоянию кодовой базы:

| Статус | Значение |
|--------|----------|
| ✅ Реализовано | Практика присутствует в коде, покрыта тестами или конфигурацией |
| 🟡 Частично | Основа есть; остался пробел или шаг по укреплению |
| 📋 Бэклог | Принято как элемент роадмапа, ещё не реализовано |

Консолидированный бэклог — в [§5](#5-дорожная-карта-внедрения-приоритизированный-бэклог). Сам по себе этот
документ не меняет поведение системы в рантайме.

## 2. Группа A — AI-инжиниринг процессов и harness-инженерия

### 2.1 Meta-Harness: сквозная оптимизация model harness (arXiv:2603.28052)
<https://arxiv.org/abs/2603.28052>

- Внешний цикл поиска по *коду обвязки* (что система хранит/извлекает/показывает), а не только промптов;
  эволюционные кандидаты оцениваются по трассам выполнения.
- +7.7 пункта к SOTA context management при 4× меньшем числе токенов контекста; переносится между моделями.
- **Статус:** 🟡 `EvalGate` + `proxy/app/shared/ab_test.py` дают оценочный цикл; автоматический поиск
  конфигураций пайплайна — бэклог (см. §5, B3).

### 2.2 My AI Adoption Journey (Mitchell Hashimoto)
<https://mitchellh.com/writing/my-ai-adoption-journey>

- Лестница зрелости из шести шагов; принудительное воспроизведение строит экспертизу; разделение
  планирования и исполнения.
- Правило harness-инженерии: каждая замеченная ошибка агента превращается в правило AGENTS.md или
  программируемый gate.
- **Статус:** ✅ мультиагентный фреймворк реализует шаги 1–5 (`artifacts/state/`, команды верификации,
  protected zones); конверсия «ошибка → gate» — постоянная политика команды.

### 2.3 «Красная книга AI-инженера» (oleg.guru/redbook)
<https://oleg.guru/redbook/ru/>

- Гл.1 «Два процесса, одна задача»: модель копроцессоров вместо «начальник—подчинённый»; эксперты HITL —
  смысловые верификаторы, а не формальная очередь. → ✅ совпадает с dual-model routing и HITL-дашбордом.
- Гл.2 «Shared state как IPC»: спека — единственный канал человек↔ИИ; адресность
  (`spec://module/doc#section`) снижает стоимость коррекции ~10×. → 🟡 в compliance-документе есть стабильные
  FR-ID; конвенция цитирования якорей зафиксирована здесь.
- Гл.3 «Архитектура памяти»: WAL как чекпоинт (перезапись каждую сессию, ≤1 страница, дата впереди,
  устаревание >24ч = предупреждение); решения требуют обоснования + условия пересмотра; секция ограничений
  защищает глобальные инварианты. → ✅ паттерн `session_checkpoint.json`; 🟡 предупреждения об устаревании и
  ссылки на обоснование у protected zones.

### 2.4 Jimmy Song — AI Native Infrastructure (jimmysong.io)
<https://jimmysong.io/book/ai-native-infra/>

- Три плоскости: Intent / Execution / Governance с замкнутыми петлями обратной связи; токены как
  управляемый ресурс первого класса; validation-first циклы; агенты — основная единица исполнения.
- Наблюдаемость обязана покрывать GPU → KV-cache → TTFT → стоимость токена, а не только утилизацию GPU.
- Фреймворк надёжности агентов: отказоустойчивость, восстановление, наблюдаемость, безопасность,
  управление состоянием.
- **Статус:** 🟡 Intent/Execution/Governance отображается на chat API+оркестратор / Qdrant+vLLM+Neo4j /
  EvalGate+canary+audit. Токенные бюджеты есть (`token_optimizer.py`), но пока не квотируются per-user (§5, B2).
  Liveness-пробы уровня оркестратора отсутствуют (§5, B5).

### 2.5 Методология СТРАТУМ (aistratum.ru)
<https://aistratum.ru/>

- LLM как детерминированные вычислительные узлы; слоистая PLA-архитектура промптов (статические блоки
  вперёд, динамические назад — дружелюбно к кэшу); RIL-слой институционализирует QA-gate «LLM-as-a-Judge».
- **Статус:** ✅ порядок сборки промпта уже статичный-первым (`context/builder.py`, принцип №3);
  🟡 вердикты judge влияют на confidence, но не жёстко блокируют выдачу (§5, B4).

### 2.6 Agent Harness: что реально строят Anthropic/OpenAI/LangChain (Habr 1023316)
<https://habr.com/ru/articles/1023316/>

- Context rot: качество падает, когда ключевой контент в середине окна; меры — компакция, маскирование
  наблюдений, just-in-time поиск, под-агенты, возвращающие короткие выжимки.
- Ярусная память: лёгкий индекс всегда в контексте → файлы деталей по требованию → сырые транскрипты только
  поиском; память — подсказка, перепроверяй по живому состоянию.
- **Статус:** ✅ `context/compression` + LongContextReorder + LLMLingua-подобное сжатие реализуют меры;
  memory-as-hint закреплён в принципах harness.

### 2.7 Дайджест Stratum: делаем стохастичный LLM детерминированным (Habr 1043198)
<https://habr.com/ru/articles/1043198/>

- «Кириллический налог»: русский текст стоит в 1.5–2× больше токенов, чем английский — бюджетирование
  обязано быть BPE-осведомлённым по языкам.
- Семейство self-audit (Chain-of-Verification, Reflexion, Self-Consistency) измеримо повышает качество.
- **Статус:** ✅ BPE-подсчёт в `token_optimizer.py`; ✅ сигналы самопроверки в `confidence.py` /
  `hallucination.py`. RU-профили бюджетов: 🟡 (§5, B2).

### 2.8 Postgres Pro: обзор meta-harness оптимизации (Habr 1045532)
<https://habr.com/ru/companies/postgrespro/articles/1045532/>

- Фронтир оптимизации сместился: промпты → параметры RAG → вся обвязка (порядок стадий workflow, профили
  инструментов, верификаторы); оценивать траектории, а не только ответы (линия OPRO / TextGrad / GEPA).
- Генетико-паретовский оптимизатор дал +24.9%/+17.6% за счёт изменения порядка стадий.
- **Статус:** 📋 Бэклог: траекторные награды из HITL-фидбэка для поиска топологии оркестратора (§5, B3).

## 3. Группа B — архитектурная практика RAG

### 3.1 Wiki-бот: Confluence → гибрид Qdrant+Elastic с RRF (Habr 980004)
<https://habr.com/ru/articles/980004/>

- HTML→Markdown до чанкования (сырой HTML ≈ нулевая информация для LLM); гибрид dense+BM25 со слиянием RRF
  лечит провалы чисто-dense поиска; RRF k≈60.
- **Статус:** ✅ точное совпадение стека: очистка в `etl/extractors/confluence.py` + гибрид RRF в `retrieval.py`.

### 3.2 RAG-ассистент MTS Web Services, части 1–2 (Habr 970392, 970476)
<https://habr.com/ru/companies/ru_mts/articles/970476/>

- Контракт антигаллюцинаций: отвечать только из предоставленного контекста, указывать URL источника,
  явный fallback-отказ.
- Размер чанка следует токенизатору эмбеддера (~10% перекрытия); метаданные включают URL и дату обновления;
  инкрементальная переиндексация только изменённых чанков.
- **Статус:** ✅ расширение `rag_sources` + модуль grounding; ✅ WAL-инкрементальный ETL + SHA-256
  content-addressed чанки; рекомендации по размерам — в ETL-гайде.

### 3.3 Графы знаний в RAG юридической предметной области (Habr 1012556)
<https://habr.com/ru/articles/1012556/>

- Vector-RAG теряет отношения на границах чанков; противоречивые версии требуют дизамбигуации через
  отношения; графы вводить только там, где метрики доказывают ценность.
- **Статус:** ✅ Neo4j-расширение опционально (`GRAPH_ENABLED`) за graceful degradation; eval-пайплайн
  (MRR/nDCG) — gate внедрения, ровно рекомендованная дисциплина.

### 3.4 Self-hosted гибридный RAG для регулируемых отраслей (Habr 1024696)
<https://habr.com/ru/articles/1024696/>

- Полностью суверенный стек: нормализация сканов Docling → BGE-M3 dense+sparse → встроенный RRF Qdrant →
  bge-reranker-v2-m3; цикл LangGraph «низкий скор → переформулировать и повторить»; лестница моделей по железу.
- **Статус:** ✅ ядро retrieval/rerank идентично; 📋 Бэклог: Docling-предобработка PDF, retry-узел
  оркестратора (§5, A2/A4).

### 3.5 Proxy-Pointer RAG (Towards Data Science)
<https://towardsdatascience.com/proxy-pointer-rag-multimodal-answers-without-multimodal-embeddings/>

- Разбор документа в дерево секций вместо скользящего окна; изображения/таблицы — артефакты с относительными
  путями; текстовых эмбеддингов достаточно — релевантность оценивается на этапе синтеза.
- **Статус:** 📋 Бэклог-апгрейд `etl/chunker`, открывающий grounded мультимодальные ответы поверх текущего
  текстового эмбеддинг-стека (§5, A1).

### 3.6 Локальный MCP-сервер знаний NOUZ (Habr 1033746)
<https://habr.com/ru/articles/1033746/>

- Типизированные метки зрелости узлов (сырой лог ≠ проверенный факт); детекция дрейфа относительно
  референсных векторов как монитор здоровья базы знаний; MCP отдаёт только явно выпущенный контекст.
- **Статус:** 🟡 MCP-сервер есть; метки зрелости + мониторинг дрейфа — бэклог (§5, A5).

### 3.7 RAG для бизнеса: архитектура и затраты (Habr 1029740)
<https://habr.com/ru/articles/1029740/>

- Компромисс RAG vs fine-tuning; оптимум чанкования 500–1500 символов с перекрытием 10–20%; качество
  источников определяет качество ответов.
- **Статус:** ✅ дефолты семантического чанкера согласованы; используется как онбординг-справочник.

## 4. Группы C/D — эффективность инференса, оценка и управление

### 4.1 Основы квантизации (Habr 1015510) и сравнение квантов MoE (Habr 1033808)

- Квантизация = сжатие весов с потерями; naive round-to-nearest ломается на выбросах; новые форматы ≠ лучше —
  проверять на конкретной модели (Q4_K_M обошёл модный вариант на 9.7 пункта перплексии на Qwen MoE).
- **Статус:** 📋 Бэклог: обязательные квант-vs-FP16 бенчмарки качества в EvalGate до рекомендации любого
  квантованного профиля развёртывания (§5, A3).

### 4.2 Спекулятивное декодирование: MTP / EAGLE-3 / DFlash (Habr 1036120)

- Draft-head спекуляция даёт безпотерные 1.5–2× ускорения; худший случай — без замедления; генерация
  упирается в пропускную способность памяти.
- **Статус:** 📋 Бэклог: бенчмарк спекулятивных флагов llama.cpp/vLLM в performance-наборе (§5, A3).

### 4.3 Стресс-тест открытых лидербордов RU/EN (Habr 1021388)

- Систематическое смещение LLM-judge (+15–30 пунктов инфляции; самопредпочтение даже вслепую): один сильный
  judge вместо комитета; Value Score = 70%·качество + 30%·log-стоимость; автоматические проверки артефактов
  (CJK внутри русского текста и т.п.).
- **Статус:** 🟡 RAGAS-регрессионное тестирование есть; формула Value Score и проверки артефактов — бэклог (§5, B1/B4).

### 4.4 Управляемая эволюция конфигураций RAG («геномы», Habr 1019018)

- Жизненный цикл candidate → evaluated → pending_approval → active над геномами промптов/роутинга/
  cache-policy; без подписи человека в прод ничего не попадает.
- **Статус:** ✅ canary + promote + одобрение HITL реализуют тот же жизненный цикл для адаптеров;
  распространение на геномы промптов/cache-policy: 📋 (§5, B3).

### 4.5 Структурные safety-ограничители (инцидент Camunda PocketOS, Habr 1036626)

- Запреты в промпте — рекомендательные, а не принудительные: убирать возможности, добавлять human-approval
  gates машины состояний, градации автономии. Ключевой вопрос: «есть ли способ, которым агент всё же сможет?»
- **Статус:** ✅ песочница инструментов + RBAC ограничивают по возможностям; разрушительные админ-операции
  (promote/rollback/canary-split) уже за ролью admin — дополнительное усиление approval-gates: 🟡 (§5, B6).

### 4.6 Локальный ИИ-ассистент как настоящий бэкенд (Habr 1048252)

- Продакшн-вызов LLM = контракт + request_id + структурные логи + тайминги стадий + источники + честный отказ.
- **Статус:** ✅ request ID, структурные логи, `rag_sources`, отказное поведение присутствуют; 🟡 разбивка
  латентности по стадиям в расширениях ответа (§5, A6).

### 4.7 Архитектурные ревью Yandex Eda (Habr 1003700)

- Обязательное RFC-ревью + tech radar предотвращают «зоопарк» инструментов; отклонённое RFC может дать
  no-code решение.
- **Статус:** ✅ Strategic Steering Committee + `[STRATEGIC_NEEDED]` gates зеркалируют это управление.

### 4.8 Книга GraphRAG (авторы Neo4j, Habr/piter 1013810)

- Граф знаний структурирует сущности/связи → grounded промпты; NL→Cypher трансляция; агентное применение графа.
- **Статус:** ✅ graph builder + multi-hop обход поставляются; NL→Cypher для живых запросов к графу: 📋 (§5, A7).
