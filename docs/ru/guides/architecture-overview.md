# Обзор архитектуры системы

Этот документ даёт высокоуровневое описание архитектуры RAG-системы — готового к продакшену, автономного,
OpenAI-совместимого RAG-прокси, который наполняется корпоративными знаниями в гибридную поисковую систему и выдаёт ответы с учётом контекста через настраиваемые LLM-бэкенды.

---

## Шестислойная архитектура

Система организована в шесть слоёв, каждый с чётко определённой ответственностью:

### 1. ETL-слой (Загрузка данных)

**Назначение:** Извлечение, преобразование и загрузка корпоративных данных в векторную и графовую БД.

| Компонент          | Ответственность                                                                  |
|:-------------------|:--------------------------------------------------------------------------------|
| Extractors         | Получение данных из Confluence, Jira, GitLab, файловых систем, книг и чат-логов |
| Semantic Chunker   | Разбиение документов на связные чанки по семантическим границам; HTML→Markdown    |
| Hash Versioner     | SHA-256 content-addressable идентификация чанков для инкрементальных обновлений    |
| Entity Extractor   | NLP-извлечение сущностей (организации, люди, технологии, концепции)               |
| Neo4j Loader       | Запись извлечённых сущностей и отношений в графовую БД                            |
| Qdrant Indexer     | Эмбеддинг чанков через BGE-M3 (dense, sparse, ColBERT) и индексация             |
| WAL Manager        | Write-ahead log checkpointing для возобновляемых инкрементальных прогонов ETL      |
| Scheduler          | Оркестрация всего пайплайна с настраиваемыми интервалами и порядком зависимостей |

**Ключевые особенности:**

- **Инкрементность по умолчанию** — WAL-checkpointing гарантирует, что переиндексируются только изменённые документы.
- **HTML→Markdown** — сохраняет структурную семантику (заголовки, списки, таблицы, кодовые блоки) при нарезке.
- **Стриминговый ETL** — обрабатывает большие датасеты ограниченными батчами, без исчерпания памяти.

### 2. Proxy-слой (RAG-обслуживание)

**Назначение:** OpenAI-совместимый API-сервер, оркестрирующий retrieval, reranking, сборку контекста и LLM-генерацию.

| Компонент             | Ответственность                                                                                       |
|:----------------------|:-----------------------------------------------------------------------------------------------------|
| API Layer (FastAPI)   | 30+ REST-эндпоинтов: chat, models, health, auth, feedback, admin, tools, files                       |
| Orchestrator          | State-graph LangGraph (10 узлов) для агентных многошаговых рассуждений                            |
| Retrieval             | Гибридный поиск (dense+sparse RRF-fusion) по Qdrant + опциональное Neo4j-расширение графа             |
| Reranker              | Cross-encoder (MiniLM-L-6-v2) реранжирует чанки для повышения точности                                 |
| Context Builder       | Сборка с ограничением по токенам, дедупликация, версионирование и сжатие                            |
| LLM Router            | Multi-provider абстракция — направляет в vLLM, llama.cpp или любой OpenAI-совместимый бэкенд       |
| SLM Router            | Облегчённая модель для fast-path задач: классификация намерений, декомпозиция запросов, NER    |
| Token Optimizer       | BPE-подсчёт, 4 стратегии сжатия, умное распределение бюджета                                       |
| Hallucination Check   | NLI-обоснование: проверка сгенерированных утверждений по контексту                              |
| Confidence Scoring    | Эвристики + SLM-pipeline верификации                                                                |
| Feedback Enricher     | Цикл самообогащения: позитивные/исправленные Q&A пары возвращаются в Qdrant                |

**Ключевые особенности:**

- **Прогрессивный retrieval** — итеративное уточнение с HyDE-расширением запросов, CRAG-оценкой и циклами рефлексии.
- **SLM-обогащение** — облегчённая модель добавляет саммари, извлечённые сущности и теги качества при индексации.
- **Контроль качества reranker** — обратная связь по чанкам позволяет майнить негативные пары для дообучения reranker.
- **Graceful degradation** — Neo4j недоступен? Пропускаем граф. Reranker OOM? Используем сырые гибридные скоры. Redis лёг? In-memory кэш.

### 3. HITL-слой (Контроль качества)

**Назначение:** Дашборд для экспертов с human-in-the-loop обратной связью, исправлениями и мониторингом качества.

- **Streamlit-дашборд** — просмотр ответов, исправления, оценка чанков, флаги устаревших документов.
- **Feedback-pipeline** — структурированная обратная связь (позитивная/негативная, исправления, релевантность чанков) возвращается в enricher и feedback store.
- **Admin-аналитика** — объём запросов, перцентили задержки, потребление токенов, топ-базы знаний, тренды активности пользователей.

### 4. MCP-сервер (IDE-интеграция)

**Назначение:** Экспонирование RAG-инструментов, ресурсов и промптов для MCP-совместимых клиентов (OpenCode, Claude Desktop).

- **STDIO-транспорт** — прямая IDE-интеграция через stdin/stdout.
- **Streamable HTTP-транспорт** — удалённые клиенты подключаются по HTTP со стримингом.
- **Tools** — RAG-поиск, листинг документов, управление KB.
- **Resources** — документы БЗ как MCP-ресурсы.
- **Prompts** — преднастроенные шаблоны для типовых паттернов запросов.

### 5. Model Evolution (Дообучение моделей)

**Назначение:** Непрерывное улучшение моделей через дообучение, оценку и безопасный деплой.

| Компонент          | Ответственность                                                              |
|:-------------------|:-----------------------------------------------------------------------------|
| SLM Trainer        | LoRA-дообучение лёгких моделей для классификации и извлечения              |
| LLM Trainer        | QLoRA-дообучение генеративных моделей                                       |
| Reranker Trainer   | Full/LoRA-дообучение cross-encoder моделей                                   |
| MLflow Tracker     | Трекинг экспериментов, логирование метрик, версионирование артефактов     |
| EvalGate           | CI/CD-шлюз качества — блокирует выкатку при регрессии                      |
| Canary Controller  | Постепенный rollout с разделением трафика (5 % → 25 % → 50 % → 100 %)    |
| Adapter Manager    | Горячая загрузка обученных LoRA/QLoRA адаптеров без рестарта сервиса     |

### 6. Agentic Tools (Расширяемость)

**Назначение:** SDK для пользовательских инструментов.

| Компонент           | Ответственность                                                   |
|:--------------------|:-----------------------------------------------------------------|
| Tool SDK            | Декоратор `@tool` с автогенерацией JSON Schema из аннотаций типов |
| Declarative Tools   | YAML/JSON определения для HTTP и shell-инструментов              |
| OpenAPI Discovery   | Авто-конвертация REST API в определения инструментов из OpenAPI |
| Tool Orchestrator   | Параллельное выполнение с DAG-разрешением зависимостей          |
| Security Validator  | Валидация ввода, песочница, rate-limit per-tool                  |

### Прогрессивный retrieval-поток

Система реализует многопроходную стратегию:

1. **Pass 1 — Начальный retrieval** — гибридный поиск по запросу, top-K = 50.
2. **HyDE-расширение** — генерация гипотетического ответа и использование как вторичного запроса, объединение через RRF.
3. **CRAG-оценка** — оценка качества; при недостаточном качестве — корректирующий retrieval с декомпозицией.
4. **Цикл рефлексии** — LLM рефлексирует над своим ответом, может запросить доп. контекст до `REFLECTION_DEPTH` итераций.
5. **NLI-обоснование** — проверка сгенерированных утверждений по контексту; флагирование галлюцинаций.

### Стриминговый ETL

1. Extractors поллят API Confluence/Jira/GitLab на изменения с последнего checkpoint.
2. Semantic chunker делит документы по естественным границам, сохраняя HTML-структуру как Markdown.
3. Hash versioner идентифицирует новые/изменённые чанки через SHA-256.
4. Embedder производит dense (1024-dim), sparse (BM25), ColBERT multi-vectors.
5. Indexer upsert-ит в Qdrant батчами по 64, с WAL-checkpointing.
6. Entity extractor идентифицирует сущности и отношения; Neo4j loader создаёт/мержит узлы графа.

## Автономная работа (air-gapped)

Система спроектирована для полностью автономной работы:

1. **Предзагрузка моделей** — `scripts/download_models_offline.py` скачивает все необходимые модели (LLM, SLM, эмбеддер, реранкер) один раз из интернета, затем передаётся через съёмные носители.
2. **Нет внешних API-вызовов** — все эмбеддинги, реранжирование и генерация выполняются локально.
3. **Локальное зеркало пакетов** — Python-зависимости могут отдаваться из локального PyPI-зеркала.
4. **Container registry** — Docker-образы собираются один раз и передаются как `.tar`-архивы.
